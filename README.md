### 🛡️ [TrustDeck](https://github.com/Gorakhnath-R-Patil/TrustDeckEngine) · live multi-tenant fraud-detection SaaS
[![Live](https://img.shields.io/badge/LIVE-trustdeck.in-0d1117?style=flat-square&logo=googlechrome&logoColor=3fb950&color=3fb950)](https://trustdeck.in)
![Java](https://img.shields.io/badge/Java_17-0d1117?style=flat-square&logo=openjdk&logoColor=ED8B00)
![Spring Boot](https://img.shields.io/badge/Spring_Boot_3.2-0d1117?style=flat-square&logo=springboot&logoColor=6DB33F)
![React](https://img.shields.io/badge/React-0d1117?style=flat-square&logo=react&logoColor=61DAFB)
![Kafka](https://img.shields.io/badge/Kafka-0d1117?style=flat-square&logo=apachekafka&logoColor=white)
![Redis](https://img.shields.io/badge/Redis-0d1117?style=flat-square&logo=redis&logoColor=DC382D)
![PostgreSQL](https://img.shields.io/badge/PostgreSQL-0d1117?style=flat-square&logo=postgresql&logoColor=4169E1)

Built for Indian fintech startups and B2B SaaS. Every transaction runs through **51 fraud signals in parallel**, and the API returns an **APPROVE / REVIEW / BLOCK** decision in milliseconds. Weighted-plus-peak scoring stops one strong signal being diluted by many weak ones.

```mermaid
flowchart LR
    C([Client]) --> A[API gateway<br/>API key + JWT · RBAC · rate limit]
    A --> E{{51 signals<br/>run in parallel}}
    E --> S[Weighted + peak<br/>scoring]
    M[ML service<br/>Isolation Forest + XGBoost] -.-> S
    S --> D([APPROVE · REVIEW · BLOCK])
    S --> K[(Kafka events)]
    S --> R[(Redis cache)]
    D --> W[HMAC-signed<br/>webhooks]
```

- 🏢 **Multi-tenancy end to end:** per-tenant rules engine, plan-based usage enforcement, Flyway-managed migrations
- 🛟 **Reliability:** Redis result caching, circuit-breaker SDKs (Java, Node.js, Python), ML microservice with fallback
- 📟 **Ops:** Prometheus alerts on error rate, p99 latency, DB pool and JVM heap
- 🧪 **Testing:** 57-test end-to-end suite, plus load / soak / spike harness and precision / recall reporting

### 🐆 [Lynx](https://github.com/Gorakhnath-R-Patil/Lynx) · stop AI agents abusing your APIs
![Open Source](https://img.shields.io/badge/Apache_2.0-0d1117?style=flat-square&logo=opensourceinitiative&logoColor=3fb950)
![Java](https://img.shields.io/badge/Java_17-0d1117?style=flat-square&logo=openjdk&logoColor=ED8B00)
![Kafka Streams](https://img.shields.io/badge/Kafka_Streams-0d1117?style=flat-square&logo=apachekafka&logoColor=white)
![Redis](https://img.shields.io/badge/Redis-0d1117?style=flat-square&logo=redis&logoColor=DC382D)
![Elasticsearch](https://img.shields.io/badge/Elasticsearch-0d1117?style=flat-square&logo=elasticsearch&logoColor=00bfb3)
![Kubernetes](https://img.shields.io/badge/Helm_%C2%B7_K8s-0d1117?style=flat-square&logo=kubernetes&logoColor=326CE5)

Autonomous AI agents can probe APIs, brute-force OAuth and inject malicious code into PRs at machine speed, and WAFs and SIEMs often miss them. Lynx detects and blocks them in real time.

```mermaid
flowchart LR
    R([API requests]) --> K{{Kafka<br/>api.requests}}
    K --> D1[API anomaly<br/>detector]
    K --> D2[Agent<br/>fingerprint]
    K --> D3[Auth anomaly<br/>detector]
    K --> D4[CI/CD<br/>scanner]
    D1 & D2 & D3 & D4 --> L[Lateral correlator<br/>MITRE ATT&CK]
    L --> B[(Redis blocklist)]
    B --> F[Filter / sidecar<br/>403 · 429]
```

- 🧠 **6 event-driven Spring Boot services:** behavioural anomaly detection, agent fingerprinting, auth-abuse scoring and campaign correlation
- ⚡ **O(1) hot path:** servlet filter or Kubernetes sidecar plus a Redis blocklist, with no model inference per request
- 🔌 **Integrations:** Kong, NGINX, Envoy, AWS Lambda authorizer, Azure APIM, GCP Cloud Run
- 🧪 **260+ tests** (unit + Testcontainers), DLQ topics with replay API, Helm + HPA, k6 load tests against a p95 < 100 ms target
